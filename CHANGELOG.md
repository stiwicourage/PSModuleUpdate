## [0.3.0] - 2026-11-16

### Added

- Add `Install-PSModuleUpdate -ReplaceUnmanagedInstallation` as an explicit,
  default-off opt-in for manually copied installations lacking root
  `PSGetModuleInfo.xml`. Install the exact planned target through the native
  provider, using Force only for a target-directory collision. Present unreadable
  or mismatching metadata still fails; identity, repository, scope, verification,
  backup, journal and rollback safeguards remain enforced.
- Add `Get-PSModuleUpdateTargetManifest` for exact-candidate manifest inspection
  from an unmodified live plan, using owned staging without installation or
  target import. Complete manifest PrivateData is returned as data only.
  An internal manifest binding rejects changed content during later install
  staging, including same-version republishing, before installed-file mutation.
  Per-call credentials, trust/license consent, source binding and cleanup remain
  enforced. Planning and install WhatIf remain acquisition-free.

### Changed

- Reuse `powershell-ci` for test/coverage, security, and publish workflows while
  retaining the six local platform/runtime lanes, their SHA pins, dependency
  isolation, skip classification, artifact checks, and 95% source-coverage gate.
  Shared callers follow the common module convention with PSScriptAnalyzer
  1.25.0, both release documents, daily tests, weekly security checks, and grouped
  weekly GitHub Actions dependency updates. PMU adds isolated dependencies and
  exact Pester 5.7.1 while shared defaults own JaCoCo artifacts and analysis. Publishing follows the
  GerberCore workflow and moves `CHANGELOG.md` and `RELEASE_NOTE.md` together.
  PSModuleUpdate references use `develop` for qualification before moving
  to a separately released shared-workflow tag.

### Fixed

- Provision exact qualified PowerShellGet 2.2.5 inside owned CI runtimes and
  verify its origin, loaded version and manifest path in the aggregate gate.
  This preserves PMU's native provider requirement when newer PowerShell
  archives bundle an unqualified version; ambient installations are unchanged.
- Isolate the Windows Documents-folder fact in installation-root tests so
  Linux runners do not depend on a host Documents folder. Native path
  selection, path-safety validation and no-write assertions are unchanged.
- Record the qualified PSResourceGet 1.2.0 availability in CI lane manifests
  even when the selected PowerShell runtime bundles a newer provider, so the
  aggregate gate does not reject an available required dependency.
- Normalize PSResourceGet's structured `PackageNotFound` discovery error to
  terminating `PMU.PackageNotFound`, including command-suffixed provider IDs.
  Missing packages produce no update plan or fallback query; provider
  diagnostics remain withheld. Unrelated discovery, authentication and
  permission failures retain their existing error contracts.

## [0.2.0] - 2026-10-27

### Changed

- Use native PowerShellGet staging and `Update-Module` for existing
  installations without Force or an install fallback, while retaining
  PSResourceGet discovery, exact target/source validation, consent and recovery.
  A worker handoff preserves the original installation lock during mutation.
  Operation-owned repository initialization handles defaults populated lazily
  during native registration, preventing intermittent pre-installation failure
  without changing the user's repositories.
  Native updates use the alphanumeric prerelease labels generated by
  Gerber/NovaModuleTools; dotted labels are outside this provider's install
  capabilities. Historical qualification does not establish untested platform
  support.

### Fixed

- Declare Microsoft.PowerShell.PSResourceGet 1.2.0 as PMU's exact runtime
  dependency so generated module manifests enforce the qualified provider
  baseline before PMU commands run.
- Linux worker ownership checks no longer reject a live approving process
  because of inconsistent cross-process timestamps. Exact PID-reuse protection
  remains enabled. Legacy Linux repository receipts require explicit recovery
  rather than automatic cleanup.
- CI dependency provisioning initializes a missing default PSGallery
  registration before downloading and removes only a registration it explicitly
  created afterward, preserving existing sources and trust. Package downloads have
  five bounded attempts against the same source, destination and pinned
  versions; exhausted downloads and isolated-import failures still fail CI
  and clean up the owned dependency directory.
- Forward the complete planned target version unchanged at the provider
  boundary instead of wrapping it in NuGet range brackets.
  Bracketed prerelease targets could be discovered but failed during staging
  from PSGallery. Exact target verification, consent and dependency checks
  remain enabled.
- Fixed installed-copy discovery failing before repository lookup when a legacy
  flat installation leaves resource directories beside numeric version folders.
  Ordinary resource folders are excluded, while numeric folders with missing
  manifests and manifest-bearing invalid layouts still fail validation. No
  installation is migrated or removed.

## [0.1.0] - 2026-10-24

### Added

- Standalone `Get-PSModuleUpdate` planning and `Install-PSModuleUpdate`
  installation contracts for explicitly identified modules and repositories,
  with CurrentUser/AllUsers scope policies and stable/prerelease selection.
  Targets may be unloaded, independent modules without a PMU dependency.
  Registered-name and explicit-URI selectors share one protocol-based
  PSResourceGet adapter, with optional credentials supplied separately to both
  operations and no implicit repository fallback.
- Strategy C safety architecture for same-numeric-base prerelease progression:
  exact staging, GUID continuity, verified backups, persistent recovery journals,
  cooperative installation locks, rollback, and complete installed-tree
  verification.
- Separate active, installed, and target version reporting and restart semantics;
  no automatic elevation, credential persistence, or module reload.
- Standalone architecture, decision, implementation, recovery, and testing
  documentation, including explicit platform and provider qualification limits.
  G-4A3 is closed as functionally complete within the recorded qualified scope,
  with explicitly accepted quality findings and preserved historical evidence.
  A proposed reusable cross-platform strategy, technology comparison, minimum
  and extended matrices, and phased roadmap separate future PMU/Gerber Core
  qualification from completed development; no testing infrastructure is added.
- Local Nova quality entrypoints with strict ScriptAnalyzer findings,
  build/unit/integration ordering, failure propagation, and formatting checks.
  Compatible installed Pester selection prevents a Pester 5/6 assembly collision.
  The shared analyzer settings exclude `PSAvoidUsingWriteHost` because host
  output is intentional; other analyzer findings remain blocking.
  Workflow policy tests retain matrix-specific restrictions for `ci.yml` while
  allowing separate publish, analysis, dependency-review, and coverage workflows.
  Shared pull-request safety checks remain enforced.
  Unit coverage is enabled with the existing 90 percent target, and the
  test/coverage CI script runs unit tests before integration tests to produce
  `artifacts/coverage.xml` for downstream coverage uploads.
- Opt-in disposable live qualification for PSGallery, NuGet.org nonmodule
  rejection, and caller-approved authenticated private feeds, with explicit
  registration cleanup and artifact-specific evidence.

### Fixed

- Pass the owned temporary dependency root between `Run Tests` workflow steps
  so NovaModuleTools is discoverable for CI and changelog validation, with
  ownership-validated cleanup even after a failed consumer step.
